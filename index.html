Failure controls

Each button changes the real simulation state.

DNS Failure

OFF

New requests cannot resolve the server address.

Database Failure

OFF

Database-dependent requests fail. Cached and static content can survive.

Server Overload

OFF

Traffic arrives faster than the server can process it. The queue grows, latency rises, then timeouts start.

Primary Server Failure

OFF

The primary server goes down. Without a backup, its traffic fails.

Backup Server

STANDBY

When enabled and the primary fails, eligible traffic reroutes to the backup. It cannot bypass a DNS failure.

Cache Behaviour

ON

When on, eligible cached responses are served without a fresh database query.

Architecture Modes

Same engine, different real-world system. Simplified educational models based on publicly known patterns — not Meta's actual internal code.

Mode: Generic Website — App → DNS → Server → Database / Cache.

Instagram flow: App → CDN Edge → Feed Service → Feed Cache / Sharded DB / Media Storage.

CDN down = photos/reels blank, text still loads. Media down = uploads fail, cached posts still viewable. Feed down = feed empty, profile still loads.

WhatsApp flow: Sender → Connection Gateway → Message Queue → Chat Server → Message Store → Receiver + Push. Server routes encrypted blobs only — it cannot read messages.

Gateway down = stuck at one tick. Queue backlog = messages delayed, not lost. Push down = delivered (double tick) but no buzz. Store down = live chat works, history won't load.

Instagram: CDN OK · Media OK · Feed OK  |  WhatsApp: Gateway OK · Queue OK · Push OK · Store OK

    Normal operation

    What happened: Requests flow browser → DNS → server → database or cache, then a response returns.

    Why: Each step depends on the previous one. DNS answers “where is this site?”, the server runs the application, and the database or cache supplies the data.

    What you observed: Cyan packets out, lime packets back, and the success rate holding near 100%.

    How it recovers: Nothing to recover — this is the baseline every other scenario is compared against.

    What this does not model: Real networks, TLS, CDNs, load balancers, or a real database. Latency here is simulated, in milliseconds, from queue depth — not measured from a live server.
